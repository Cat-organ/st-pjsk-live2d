一、怎么测试
--------------------------------------------------------
整个文件夹就是「素材根目录」，起一个 HTTP 服务指向它：

    cd /d K:\st-pjsk-live2d
    python -m http.server 8933

然后打开  http://127.0.0.1:8933/pjsk-game.html

不要直接双击 html（file:// 不跑 ES module，会一直停在加载）。
页面里的 assetBase 是 ./，运行时会转成当前地址，换端口 / 换路径都不用改。

三、上传时放哪
--------------------------------------------------------
把本文件夹里的内容整体当成素材根目录（下面用 <根> 表示）：

  <根>/player/bundle.js         播放器本体
  <根>/models.json              模型索引
  <根>/backgrounds.json         背景索引
  <根>/model_manifest.json      服装 → 模型文件 + 动作目录
  <根>/live2d/  <根>/motions/   人物模型与动作
  <根>/background/  <根>/ui/  <根>/fonts/  <根>/Profile/  <根>/worldmap/  <根>/fx/

服务器必须开 CORS（Access-Control-Allow-Origin: *），
否则背景能显示、但 Live2D 人物会加载失败（moc3 / 贴图是 fetch 取的）。
传完用 curl -I 看一眼响应头里有没有这个字段。

七、酒馆那边
--------------------------------------------------------
两种情况，只看你用的是哪种捕获：

A. 用 <StatusPlaceHolderImpl/> 占位符（你现在这种）
   正则不用动，只把 regex-replacement.txt 重新粘一遍（页面代码变了）。
   前端会整条消息读取，再自己取最后一个 <game> 块。
   注意：这种方案下消息里的 <game> 原文会留在聊天记录里，
   要藏起来需要另加一条「仅格式显示、替换为空」的规则。

B. 用 <game> 正则直接替换
   正则换成只吃最后一个 <game> 的版本：

       <game>(?![\s\S]*<game>)([\s\S]*?)</game>

   旧版 <game>([\s\S]*?)</game> 会因为思维链里没闭合的提及而吞掉整段思考。

两种都要注意：regex-replacement.txt 里的 assetBase 还指着
http://127.0.0.1:8931/pjsk-assets/ ，上传拿到真实域名后必须重新构建：

    python tools/build_player.py --asset-base https://你的域名/路径/

结尾的 / 不能少，然后把新生成的 regex-replacement.txt 粘进去。
